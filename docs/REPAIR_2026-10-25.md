# Production investigation and resume repair — 25 October 2026

The user reported broken payment, resume extraction and other website actions.
They subsequently said they would handle the Stripe test key, so no payment
credentials, checkout restrictions or payment configuration were changed.

## Reproduced causes and current boundaries

- Production was running e392dc7. Web, Caddy and application-worker services were
  active; disk and memory did not indicate a current outage.
- The stored scanned, two-column resume yielded 4,746 characters, but only contact
  suggestions. OCR put sidebar headings before main-column paragraphs, decorative
  headings did not match section names, and dates between employer and role were
  not recognized. This was a real extraction/parsing failure.
- The saved owner profile is unverified with empty employment, education and
  project sections. Application preparation correctly requires profile review;
  the old error confusingly instructed web users to edit profile.json.
- Live discovery returned 297 postings without source warnings. A minimal Gemini
  provider request returned a response. These checks establish provider response,
  not universal job coverage or action-capable AI assistance.
- Gmail configuration exists, but the owner workspace has no consent token.
  Reading a real mailbox remains dependent on the account holder connecting it.
- No employer origin adapters are configured. Automatic employer form execution
  remains unavailable; localhost tests do not establish real ATS coverage.
- Stripe is in test mode. Real customer billing remains unfinished.

## Repair

Resume OCR now requests TSV word positions alongside text and recognizes a
substantial gutter with text on both sides before reading columns separately.
Uncertain/single-column layouts retain Tesseract's original text order. The
parser accepts decorated known headings and explicit employer/date/role layouts,
preserving already identifiable adjacent job records. Skill cleanup preserves
C++/Notepad++ and parenthetical lists. Source text still needs user review;
suggestions do not assert that OCR spellings or ambiguous facts are correct.

The profile verification error now explains the web action needed, with a link
back to Profile. Approval requirements were not bypassed.
