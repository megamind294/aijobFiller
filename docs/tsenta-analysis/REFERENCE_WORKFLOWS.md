# Tsenta reference workflow inventory

## Evidence boundary

This is a **historical October 15, 2026, Europe/Warsaw inventory**, extracted from the two user-supplied consolidated reports. It is **not fresh runtime proof**, a source-code analysis, or a statement that all reference features work today. No Tsenta page was accessed for this inventory. Source `M` means `docs/jobpilot-master-observations.md`; source `D` means `docs/jobpilot-master-observations 1`. Both contain the same 509-line consolidated report; citations below use `M` line numbers, also applicable to `D`.

Labels: **Observed UI** = visible control/state documented by the prior inspection; **Observed execution** = explicitly exercised behavior; **Connector read** = historical authenticated tool result; **Claim** = marketing, interface explanation or chatbot output; **Unknown** = not established. Controls alone do not prove their backend works. Private screenshots, attachments and account identifiers referenced by the reports should stay local, not be republished. [M:3–9, 473–475]

## Exercised end-to-end paths and factual pitfalls

1. **ElevenLabs single Apply:** authorized action → processing → one available credit deducted/reserved → optimized single-column PDF ready → filled form → paused final review. `PENDING_SUBMIT_REVIEW`, **unsent**; no employer receipt. Generated narrative included methods not explicit in source. [M:156–160,190–215]
2. **Hostinger supplied URL:** detect Ashby → load description → optimized document → fill → paused review, another available credit reserved, **unsent**. Generated attachment added SQL/ORM/Jest/testing and other employer-specific claims not uniformly confirmed. Contractor/future-contact consents and “Negotiable” compensation were preselected; observation is not acceptance. [M:162–184]
3. **Profile correction:** corrected degree major/date in saved profile, but an older application attachment retained old facts. Editable source, current preview and exact employer attachment are distinct artifacts. [M:213–219]
4. **Matching/search:** frontend chip and matching feed observed; async stale/empty interim states occurred. Score source, probability interpretation, ranking implementation and data supply are unknown. [M:149,221–225,259–279]

## Claims that must not become asserted implementation facts

- Marketing/free-grant and sign-in options are not exercised onboarding or universal messaging APIs. [M:28–35]
- Lanes, cap and schedule configuration do not establish unattended successful applications. [M:243–269]
- A match percentage does not establish ATS pass probability; source-supported rewording does not validate new claims. [M:211–225]
- Indeed UI does not identify the entire supplier pipeline; public listing APIs do not grant employer application-submission access. [M:275–281]
- Mobile swipe affordance is not tested gesture behavior, a native mobile app binary, or a proven iOS/Android API. No mobile package was analyzed in these reports. [M:74–78,473]
- Extension advertisements, MCP client controls, email integration toggles, portfolio/referral controls and password settings do not establish the full remote/backend implementations. [M:99,275,473]
- User's earlier marketing narrative (50,000 pages, 19 ATSes, WhatsApp/iMessage submissions, automatic recruiter routing) is **not corroborated runtime evidence in these two files**.

## JobPilot design requirements, not Tsenta observations

The report's §11 is explicitly a proposed build handoff. It proposes: shared authorized services for web/chat/MCP/worker; employer registry/ingestion/dedup and four timestamps; hard constraints plus explainable matching; original upload → OCR → verified profile → immutable job-specific documents; fact-linked diff and independent document/form approvals; fail-closed unsupported review; atomic shared caps/credit reservations/idempotency; hosted checkout/webhooks; owner server-role exemption; identity linking; consistent cover-letter policy. These are good acceptance targets, **not recovered Tsenta internals**. [M:305–443]

Historical provider choice (OpenAI), suggested database/queue technology, exact initial build order and PLN markup are dated design choices, not a claim about current JobPilot configuration or Tsenta source. Current user decisions may supersede them. [M:301,307,337,371–411,445–453]
